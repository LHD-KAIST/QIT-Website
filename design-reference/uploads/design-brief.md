# KAIST Physics QIT — 연구실 웹사이트 디자인 브리프

## 이 문서를 읽는 법

KAIST 물리학과 양자정보이론 연구실 웹사이트를 새로 만든다. 정적 사이트다.
이 문서는 **시각 디자인 시안과 디자인 토큰**을 요청하는 브리프다.
데이터·정보구조는 이미 확정되어 있다(첨부 JSON 3종). 그대로 따른다.

한 문장으로: **정보를 최소한으로 노출하면서, 과시하지 않고, 실적이 스스로 증명되게 하는 사이트.**

---

## 1. 이 연구실이 어떤 곳인가

KAIST 물리학과 양자정보이론 그룹. PI는 오창훈 조교수. **2024년 4월 창립.**

무엇을 연구하나: 양자 컴퓨터가 할 수 있는 것과 고전 컴퓨터가 할 수 없는 것 사이의 **경계**.
그 경계가 어디인지 찾고, 문제가 어느 쪽에 속하는지 증명한다.

**드러나지 않아야 하지만 반드시 느껴져야 하는 사실**:
창립 2년여 만에 논문 34편(Science 1, Nature Communications 2, Nature Physics 2, PRL 3,
PRX Quantum 3, npj QI 3). 구성원 12명 중 학생이 10명이고, 학생이 제1저자인 논문이 7편,
그중 하나는 학부생이 제1저자다.

→ 이 그룹은 **젊고 빠르고 학생이 논문을 주도하는** 곳이다. 오래된 권위가 아니라 속도와 밀도가 색깔이다.

## 2. 가장 중요한 원칙 — 과시하지 않는다

의뢰인의 명확한 요구다. **숫자로 실적을 외치지 않는다.**
"34편", "피인용 N회", 커다란 통계 배너, 성취를 나열하는 배지 벽 — **전부 금지.**

대신 **증거를 조용히 놓는다.** 논문 목록이 알아서 말하게 한다.
홈에 대표 논문 몇 개를 놓으면 거기 붙은 *Science*, *Nature Physics* 배지가 저절로 실적을 전한다 —
우리가 "우리 대단해요"라고 말하지 않아도. 이것이 이 사이트의 톤이다:
**자랑하지 않는 자신감. 아는 사람은 목록 한 번 보면 안다.**

무게 중심: **홈은 비운다. 정보의 무게는 전부 Publications 페이지로 보낸다.**
궁금한 사람만 한 번 더 눌러서 34편을 본다. 첫인상은 고요해야 한다.

## 3. 정보 구조 — 페이지별로 "화면에 실제로 남는 것"

기존 사이트의 실패는 **모든 페이지가 정보로 꽉 차 있던 것**이다. 새 사이트는 한 겹씩 숨긴다.

### Home
- **첫 화면(스크롤 전): 정체성 한 문장. 그게 전부.** 숫자 없음, 배지 없음, 통계 없음.
  - 문장 후보(방향 확정됨, 표현은 다듬어도 됨):
    "We study the boundary between what quantum computers can do and what classical ones cannot."
- 스크롤 ① 연구분야 3개 — 이름 + 한 줄 요약만. 클릭 시 Research로.
- 스크롤 ② Selected papers 3~4편만(highlight에서 추림). "대표작"이라 외치지 말고 조용히 놓는다.
- 스크롤 ③ 위치·연락처 + Join 링크.

### Research
- 분야 3개. 각 분야 = 제목 + 두세 문장 + figure 하나 + "See all papers →"(해당 태그로 필터된 Publications로).
- 관련 논문을 여기 나열하지 않는다. 링크로만 보낸다.

### Publications — 여기가 정보를 다 받는 곳
- 기본 정렬: **연도 내림차순**, 같은 연도 안에서는 order 오름차순.
- 연도가 구분자(2026 / 2025 / 2024).
- 상단 태그 필터. 각 칩에 논문 개수 표시(예: `Boson Sampling 10`). 개수는 빌드 타임 계산.
- **태그 클릭 시 URL에 상태**: `/publications?tag=boson-sampling` (공유·뒤로가기·북마크 가능).
- 저널/프리프린트 토글. 필터 적용 중 상태와 해제 방법이 분명해야 함.
- 결과가 1편일 때도 어색하지 않아야 함(논문 1편짜리 태그가 7개 있다).

### People
- 첫 화면: 사진 + 이름 + 역할 + 한 줄, 격자로. **interests·학력·이메일은 카드 클릭 시 펼침.**
- 역할 순서: PI → Postdoc → Grad → Undergrad → RA →(Alumni, 지금 0명이지만 자리 남길 것).
- 그룹 사진 자리.

### Join
- 세 문장이면 충분: 무엇을 찾는가 / 누구를 환영하는가 / 어떻게 연락하는가.
- 기존엔 이메일 한 줄뿐이었다. 이 페이지가 사이트에서 두 번째로 중요하다(대학원 지원자 유입).

## 4. 데이터 구조 (첨부 JSON)

세 파일이 서로 연결돼 있다. 디자인은 이 필드를 전제한다.
tags.json ──tag id──▶ publications.json ──memberId──▶ members.json

### tags.json — 28개
- kind:"area" 3개(Research 분야): quantum-learning(논문 10) · nisq(20) · metrology(7)
- kind:"keyword" 25개(필터용): 상위 Noise&Loss 12 · Classical Simulation 10 · Boson Sampling 10 …
  하위엔 논문 1편짜리 태그가 7개.

### publications.json — 34편
필드: title, authors[], year, order, type(journal|preprint), venue(배지용 짧은 이름),
citation(전체 인용문), url, tags[](3~4개), highlight(6편), note(예: "Editors' Suggestion").
authors[] 각 항목: name, group(연구실원 여부), corresponding(교신저자), memberId.
- **저자 수가 1명(Oh 단독)부터 15명(Science)까지.** 한 컴포넌트가 양극단을 다 견뎌야 한다.
- 연도: 2026=15 / 2025=10 / 2024=9. 타입: 저널 19 / 프리프린트 15.

### members.json — 12명
역할 6단계: pi(1)·postdoc(1)·grad(5)·undergrad(4)·ra(1)·alumni(0).
필드: name, roleLabel, affiliation, emails[], photo, bio, education[], interests[],
links{scholar,website,arxiv,orcid}, period, nextPosition.
**데이터 현실**: bio는 한 문장. 학부생은 bio 없이 학위 한 줄만. links는 현재 PI만 채워짐 —
**링크·사진·bio가 비어도 카드가 안 무너져야 한다.** 사진은 아직 준비 중(플레이스홀더 전제).

## 5. 디자인 방향 — 여기가 핵심

첫 시안이 "구렸다"는 피드백을 받았다. 아래는 그걸 반복하지 않기 위한 구체적 지침이다.

### 5.1 왜 학술 사이트는 대개 못생겼나 — 피할 실패 유형
- **부트스트랩 기본값**: 파란 링크, 회색 카드, 균일한 그림자, radius 8px 둥근 모서리. "관리자 페이지" 냄새.
- **꽉 찬 화면**: 여백 공포. 모든 영역을 콘텐츠로 채움. → 우리는 정반대로 간다. 여백이 콘텐츠다.
- **장식용 스톡 이미지**: 악수 사진, 추상적 "기술" 그래픽, 웃는 연구원 스톡. 전부 금지.
- **무의미한 그라디언트 히어로**: 보라→파랑 그라디언트 위 흰 제목. 2015년 스타트업 냄새.

### 5.2 양자 연구실 사이트의 클리셰 — 특히 강하게 피할 것
- 검은 배경 + 네온 파랑/보라 + 블로흐 구체 + 얽힌 입자 렌더
- 우주·성운 배경, "양자 컴퓨터 샹들리에" 스톡 사진
- 떠다니는 큐비트, 의미 없는 파티클 애니메이션
- 근거 없는 01 / 02 / 03 번호(연구분야 3개는 **순서가 없다**. 순서를 암시하지 말 것)

### 5.3 AI가 디자인할 때 흔히 도망가는 기본값 — 이것도 피할 것
아래 세 가지는 "선택"이 아니라 "기본값"이라 아무 브리프에나 똑같이 나온다. 여기에 안주하지 말 것:
1. 크림색 배경(#F4F1EA류) + 고대비 세리프 + 테라코타/점토색 액센트
2. 거의 검은 배경 + 형광 그린/버밀리언 액센트 하나
3. 신문 레이아웃 + 헤어라인 괘선 + radius 0 + 빽빽한 다단
이 중 하나로 자동 수렴하지 말고, 이 브리프의 주제에서 색과 형태를 끌어낼 것.

### 5.4 그럼 무엇을 하나 — 이 연구실의 실제 재료에서 언어를 뽑는다
스톡 "양자" 이미지 대신, 이 그룹의 **논문에 실제로 등장하는 형태**에서 시각 언어를 만든다.
(별도로 논문 figure 2~3장을 레퍼런스로 첨부한다. 각 figure는 "복제하지 말고 파생시켜라" —
색(colormap)이 아니라 기하와 리듬만 가져올 것.)

가능한 원천:
- **위상공간(Wigner 함수)**: 원점 대칭 + 간섭 줄무늬 → 히어로 배경 텍스처, 시그니처 요소
- **광학 회로 / 빔스플리터 격자**: 선과 노드의 그리드 → 구분선, 레이아웃 골격, nav 언더라인
- **복잡도 상전이 곡선**: 영역을 가르는 경계선 → 섹션 구분, 필터 UI의 은유
- **회로도**: 등간격 수평선 + 게이트 박스 → 목록 정렬 규칙

이것들은 정직하다(우리 연구다) + 동시에 낯설다(남이 안 쓴다). 세상에 하나뿐인 정체성이 여기서 나온다.

### 5.5 타이포그래피가 인격이다
서체 페어링에서 승부를 본다. 아무 프로젝트에나 쓰는 조합 말고, 이 브리프에 맞는 선택.
- 물리 그룹이니 **수식 친화적**이어야 한다. 논문 제목에 Cramér–Rao, ×, –, 유니코드 인용부호,
  그리스 문자가 섞여 있다. 이 글자들이 깨지거나 폴백 폰트로 튀면 즉시 아마추어처럼 보인다.
- display / body / 데이터·캡션용 utility, 최소 3역할의 명확한 위계.
- 논문 인용문(작고 촘촘한 텍스트)이 우아하게 읽히는 게 이 사이트의 숨은 관건이다.

### 5.6 대담함은 한 곳에만
시그니처 요소 **딱 하나**에 시각적 위험을 몰고, 나머지는 전부 조용하게.
논문 34편을 읽으러 온 사람이 방해받으면 안 된다. Chanel의 규칙: 나가기 전 거울 보고 액세서리 하나를 뺀다.

## 6. 필요한 컴포넌트

1. **PublicationItem** (가장 중요, 34회 반복) — 제목(링크) / 저자(연구실원 강조·교신저자 `*`) /
   venue 배지(저널 vs arXiv 구분) / 인용문 / 태그 칩 / note. 저자 1명과 15명이 같은 리듬으로.
2. **TagChip** — 라벨 + 개수, 상태 3종(기본·호버·선택), area와 keyword 시각 구분.
3. **MemberCard** — 사진·이름·역할·소속·bio·interests·링크·논문 수. 빈 필드 견딤. 클릭 시 펼침.
4. **ResearchAreaBlock** — 제목·요약·설명·figure·"See all papers →".
5. **공통** — Nav(모바일 포함)·Footer(주소·연락처)·페이지 헤더.

## 7. 요청 산출물 (이 순서대로)

1. **디자인 토큰** — 컬러 4~6개(명명된 hex, 라이트/다크) · 타이포(역할별 실제 서체명) ·
   타입 스케일 · 스페이싱 스케일 · 라운딩 · 보더. **왜 이 선택인지 한 줄씩.**
2. **컴포넌트 시안 5종** (6장, 각 상태 포함)
3. **Home 히어로 시안 2~3안** — 접근이 서로 달라야 함(예: 순수 타이포 / figure 파생 그래픽 / 여백 극대화)
4. **Publications 페이지 시안** — 필터 적용 전/후 둘 다
5. **시그니처 요소 1개** — 이 사이트를 기억하게 만들 단 하나. 무엇이고 왜인지 설명.
